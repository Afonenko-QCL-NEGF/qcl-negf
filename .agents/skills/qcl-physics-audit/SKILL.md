# Аудит физики и численной схемы

Начать с физического утверждения и реальной модели архивного запуска.
Прочитать применимые AGENTS.md; если навык перенесён отдельно, всё равно
ограничиться порученным аудитом, без изменений и новых расчётов.

1. Установить версии кода, плана, модели и артефактов. Различать заявленную
   теорию, реализацию и измеренные результаты. Конфликт сохранить в отчёте.
2. Построить цепочку: источник/формула → предпосылки → оператор/дискретизация →
   path/symbol → наблюдаемая/критерий → существующее свидетельство.
3. Проверить конвенции, размерности и нормировки; применимость сохранения
   частиц/энергии, причинности, спектральных правил и равновесных пределов
   по [памятке](references/physics-checks.md). Не придумывать универсальные пороги.
4. Разделить raw fixed-point residual, величину смешанного шага, внутренний
   SCBA и внешний Poisson. Финальная проверка должна относиться к одному
   согласованному состоянию U/G, а не к predicted U и старому G.
5. Отдельно оценить шаг/окно энергии, k-плотность/cutoff, пространственную
   сетку, базис/периоды/embedding и scattering quadratures. Изменение одного
   направления локализует ошибку; одновременное изменение всех — нет.
6. Проверить независимость oracle: общие kernels у reference/optimized
   оставляют общий риск. Для эксперимента сверить условия, единицы и неопределённость.
   Согласие с calibration data не объявлять независимой валидацией.
7. Для спорного вывода поручить независимую проверку исходных формул/данных
   без подсказанного диагноза, если доступны субагенты. Затем разобрать возражения.

Выдать findings: утверждение; категория (наблюдение/вывод/гипотеза);
точный источник; предпосылки; влияние на научный вывод; контраргумент;
самая дешёвая различающая проверка; решение «сохранить / изменить / измерить».
Для каждого уровня отдельно указать подтверждено, опровергнуто или неизвестно:
итерационная сходимость, физические gates, дискретизация, эксперимент.
Недостающий опыт предложить с бюджетом; не выполнять в рамках read-only аудита.
