# Аудит физики и численной схемы

Начать с проверяемого физического утверждения и доступных первичных материалов. Для source-only
аудита выбрать модель/код и owning equations; архивный run не обязателен. Для вывода о конкретном
run установить именно его archived model, source, frozen plan/criteria и данные; current
README/defaults их не заменяют.

При доступном checkout прочитать применимые AGENTS.md и developer loop `CONTRIBUTING.md`; выбирать
D/L/N/S проверку по фактическому действию. В standalone опираться на
[три маршрута памятки](references/physics-checks.md) и её essential task content: разбирать
доступные материалы, назвать точный missing owner/path/version и ограничить зависимый claim, не
требуя отсутствующий root. Последнее применимое поручение определяет этап; historical PLAN не
отзывает active grant. Уже разрешённые bounded checks внутри него не пересогласовывать, grant
сохраняется при review/commit/resume. Missing блокирует только dependents. Навык сам не разрешает
изменение модели/кода, solver или setup. Выполнять уже порученный этап без повторного запроса; fresh
inventory, защита host/foreign ресурсов и technical gates сохраняются. Не вводить обязательный общий
campaign CPU/RAM/time/attempt budget или исторический CI-once. Явные ограничения конкретного
поручения и численные stopping criteria сохраняются.

1. Установить версии выбранного кода/модели и, для result claims, архивного плана/артефактов;
   недоступное отметить. Различать заявленную теорию, реализацию и измеренные результаты. Конфликт
   сохранить в отчёте.
2. Построить цепочку: источник/формула → предпосылки → оператор/дискретизация → path/symbol →
   наблюдаемая/критерий → существующее свидетельство.
3. Проверить конвенции, размерности и нормировки; применимость сохранения частиц/энергии,
   причинности, спектральных правил и равновесных пределов по
   [памятке](references/physics-checks.md). Не придумывать универсальные пороги.
4. Разделить raw fixed-point residual, величину смешанного шага, внутренний SCBA и внешний Poisson.
   Финальная проверка должна относиться к одному согласованному состоянию U/G, а не к predicted U и
   старому G.
5. Отдельно оценить шаг/окно энергии, k-плотность/cutoff, пространственную сетку,
   базис/периоды/embedding и scattering quadratures. Изменение одного направления локализует ошибку;
   одновременное изменение всех — нет.
6. Проверить независимость oracle: общие kernels у reference/optimized оставляют общий риск. Для
   эксперимента сверить условия, единицы и неопределённость. Согласие с calibration data не
   объявлять независимой валидацией.
7. Для спорного вывода поручить независимую проверку исходных формул/данных без подсказанного
   диагноза, если доступны субагенты. Затем разобрать возражения.

Выдать findings: утверждение; категория (наблюдение/вывод/гипотеза); точный источник; предпосылки;
влияние на научный вывод; контраргумент; самая дешёвая различающая проверка; решение «сохранить /
изменить / измерить». Для каждого уровня отдельно указать подтверждено, опровергнуто или неизвестно:
итерационная сходимость, физические gates, дискретизация, эксперимент. Для недостающего опыта
описать различающее свидетельство, измеряемую стоимость, ресурсы/резервы и stop condition; выполнять
только в порученном этапе. Для R00 действуют scoped инструкции программы: вывод в чате, без экспорта
или сохранения старых результатов, массивов, history и checkpoint.
