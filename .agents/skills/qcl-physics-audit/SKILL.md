# Проверка физического утверждения

Установи вопрос и минимальные источники: уравнение/конвенцию, точную ревизию
затрагиваемого кода, необходимые входы. Архивный run нужен для вывода о run,
но не для проверки размерности формулы. Не собирай паспорт всего проекта.

Проследи: предпосылки → уравнение → дискретизация/мера → функция → наблюдаемая
→ критерий → свидетельство. Для существенного вывода укажи воспроизводимый
локатор. Документация показывает намерение; реализацию проверяй отдельно.

Выбери проверки по рассматриваемому механизму из
[карты применимости](references/physics-checks.md). Не превращай её в полный
чеклист каждого изменения; указанные там исторические ревизии не задают текущий код.
Учитывай единицы, знаки, матричные свойства, интеграционные веса, края окна,
контакты и baths там, где от них зависит утверждение.

Отделяй raw residual от mixed step и научную проверку от успешного завершения.
Для околонулевых величин обоснуй абсолютную часть допуска. Равновесную FDR
применяй при согласованных μ/T и baths, а не только при нулевом bias.
Успех manufactured operator case не доказывает сходимость реальной QCL-задачи.

Проверяй независимую опору: общий reference/optimized код может разделять ошибку.
Различай наблюдение, вывод и гипотезу; укажи ограничение и дешёвый способ
разрешить оставшееся сомнение. Разрешённые научные варианты сохраняй отдельно
от baseline. Дополнительные эксперименты выполняются по полномочиям поручения,
без повторного согласования уже разрешённого этапа.
