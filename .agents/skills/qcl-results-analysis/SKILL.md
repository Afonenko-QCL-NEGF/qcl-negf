# Анализ существующих результатов

Работать с неизменяемыми исходными архивами. Соблюдать порученный объём анализа;
новые solver runs, изменения физики и benchmarks не входят в этот навык.
Применимые инструкции репозитория читать отдельно; навык не расширяет полномочия.

1. Составить inventory: размеры, hashes, части/receipts, study/run/attempt,
   контракт, checkpoint/analysis distinction. Проверить полноту и доступность.
   Не исполнять вложенные скрипты; распаковывать в отдельный каталог после оценки
   места, безопасных путей и распакованного объёма.
2. Использовать совместимый reader owning package. Не интерпретировать старый
   контракт как новый по похожим именам. При несовместимости обозначить предел
   чтения; не мигрировать исходные массивы молча.
3. Сопоставить архивные commits, frozen plan, configuration hash и native
   payload provenance. Если текущий код другой версии, разделить его аудит
   и интерпретацию архива до установления совместимости.
4. Прочитать HDF5 schema, shapes, dtypes, units, оси и веса до массивов.
   Читать нужные slices/chunks, не загружать весь набор. Оценить рабочую память
   с распаковкой и временными копиями. Повторно использовать проверенный inventory.
5. Разделить snapshot consistency, process completion, convergence,
   scientific acceptance и experimental validation. Отличать `pass`, `fail`,
   `not_measured`, `not_applicable` с основанием и `error`. Прерванные попытки
   и непринятые результаты оставить в анализе, не отбирать только успешные.
   Согласованность экспортного snapshot означает целостный срез артефактов;
   она не равна физической согласованности пары U/G. Ошибка одной не определяет
   автоматически статус другой; архивные статусы не переписывать из предположения.
6. Строить историю по point/attempt/restart, raw residual и остановкам;
   не склеивать счётчики итераций различных состояний. Проверить, какие массивы
   относятся к одному U/G. Для тонких физических выводов применить physics audit.
7. Перед сравнением заполнить [матрицу сопоставимости](references/comparison.md).
   Изменение модели не называть ускорением. Применять сохранённые определения
   метрик; любую независимо пересчитанную оценку обозначать как derived.
8. Подготовить воспроизводимые таблицы/графики: hash + dataset + slice + units
   + transformation + версия analysis code. Сохранять derived отдельно.

Выход: inventory и пробелы; сопоставимые группы; таблица выводов с точными
свидетельствами и неопределённостью; что сохранить/изменить/измерить;
следующий различающий шаг. Если данных недостаточно, локализовать пробел и
его влияние, не объявлять ни физический успех, ни ошибку solver без основания.
RO-Crate пока задача развития: не предполагать его наличие в текущем экспорте.
