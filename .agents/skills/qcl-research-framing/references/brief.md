# Контракт исследовательского запроса

Это предметные подсказки к [навыку постановки](../SKILL.md), а не вторая обязательная форма задания.
Если доступен общий checkout, используй канонический developer loop `CONTRIBUTING.md`. Не добавляй
регистрацию или новый approval checkpoint. Заполняй только существенное; неизвестное отмечай, а не
угадывай.

## Выбор источников

| Маршрут                    | Что нужно для постановки                                                                                                                                                                 | Граница вывода                                                                                                                                                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Текущий source-only        | Проверяемое утверждение о модели/коде, выбранные source refs, paths/symbols, применимые инструкции; actual HEAD/dirty/gitlinks различаются                                               | Архивный run не обязателен. Можно подготовить source-аудит или ограниченный опыт, но чтение реализации не доказывает runtime/physics result.                               |
| Неизменяемый архив         | Archived source/model identity, frozen plan, run/attempt, artifact hashes, комплектность, доступные dataset paths; совместимость reader устанавливается по объявленному контракту архива | Текущий README не заменяет архивный contract или source. Missing raw ограничивает только зависимый result claim; исходные массивы не переписываются.                       |
| Отдельная установка навыка | Переданные материалы и их версии, текущий запрос и разрешённый этап; skill package с этой reference достаточен для подготовки вопроса                                                    | Checkout не обязателен. Назови точный недоступный owning документ/commit или artifact; не реконструируй его содержание по названию и не устанавливай reader автоматически. |

В standalone-задании достаточно явно записать вопрос/решение и owner/роль, immutable inputs и их
доступность, порученный этап/пути/полномочия, сохраняемые invariants, oracle/уровень acceptance и
протокол проверки, зависимости, известную стоимость, ресурсы/резервы и остановку и
выход/ограничения/resume. Это содержание сообщения или существующей карточки, не новый обязательный
шаблон. Отсутствующий root contract не запрещает постановку с явными unknowns; missing блокирует
только зависимое действие или утверждение.

## Подсказки к научному brief

| Предмет               | Что уточнить                                                                                                                                                                  |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Вопрос и решение      | Какая наблюдаемая/механизм исследуется; какое решение изменит ответ                                                                                                           |
| Физическая постановка | Прибор, температура, bias на период/весь прибор, контакты/периодичность, активные механизмы, единицы; known/unknown и assigning source                                        |
| Гипотезы              | Альтернативы и наблюдения, которые способны их различить                                                                                                                      |
| Свидетельства         | Выбранные source commits и dirty overlays, литература/формулы, study/run/attempt, archives/checksums, dataset paths и slices                                                  |
| Сопоставимость        | Что фиксировано; что меняется; reference и его независимость; архивная и текущая версии не смешиваются                                                                        |
| Приёмка               | Наблюдаемые, применимость, units/weights/near-zero, абсолютные/относительные допуски и их основание из owning contract; ошибки и missing                                      |
| Полномочия            | Только постановка / source audit / анализ готовых данных / изменение / конкретный вычислительный этап; уже выданные права не спрашивать повторно                              |
| Стоимость и остановка | Для предложенного или порученного опыта: измеряемые CPU/RAM/wall/I/O/output, реальные резервы, stop/resume и явные ограничения пользователя; без универсальной campaign quota |
| Выход                 | Реестр утверждений и доказательств; сохранить/изменить/дополнительно измерить/данных недостаточно; ограничения и следующий шаг                                                |
| Неизвестные           | Блокирующие и неблокирующие; что можно сделать уже сейчас                                                                                                                     |

Пример цели: установить, позволяют ли имеющиеся архивы принять стационарный транспортный результат
при выбранных условиях и что ограничивает доказательность. Не подменять её требованием обязательно
найти ошибку или получить accepted status.

## Где искать owning смысл

Пути ниже repository-relative; это locators, а не обещание наличия root в standalone. Проверка
доступности путей — 2026-10-19; при повторном использовании сверь selected Gitlinks/commit и
фактический source, не обновляя их до latest.

- `components/qcl-negf-research/docs/scientific-inputs.md`: model/study sources, условия и границы
  сопоставления; выбранная архивная постановка важнее current defaults.
- `components/QCLNEGF.jl/docs/src/physics/numerical-policy.md` и `docs/src/theory/12_validation.md`
  внутри Core: смысл проверок и уровни доказательности.
- `components/QCLNEGFRunner.jl/docs/src/user/results.md`: качество, checkpoint и restart.

Вне checkout запиши, какой из этих документов какой версии нужен для конкретного вывода. Отсутствие
материалов не разрешает выдумать физическую формулу, допуск или формат. Условия остановки: вопрос
разрешён в заявленных пределах; данных недостаточно для различения альтернатив; достигнуто явное
ограничение поручения; следующее действие выходит за этап. Новый
solver/benchmark/build/install/server stage не следует из готового brief. Уже порученная работа
продолжается в своём scope; fresh admission и technical BIND/READY там, где они обязательны,
сохраняются.
