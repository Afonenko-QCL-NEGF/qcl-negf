# Кампания 133: скрипты и входы

Этот набор сохраняет скрипты и входы без изменения их байтов для воспроизведения; он не является научной приёмкой результатов. Исходные массивы находятся на VM и в набор не включены. Для скриптов нужна активная среда Julia Pkg с Core (`QCLNEGF`), Runner (`QCLNEGFRunner`), Unitful, HDF5 и FFTW.

`run_inner_v1.jl` относится к B0, `run_inner_markers_v2.jl` — к S01 с фиксированным U; Poisson в этих опытах не выполняется. Исторический S01 следует рассматривать отдельно от B0. Файлы в `inputs/` сохраняют исходные входы и не должны изменяться для воспроизведения соответствующих опытов. `validation/` содержит проверки прямого и standalone путей, `oracle/` — скрипт и входы oracle.

Известное ограничение v2: `save_first_state` при `callback cadence 0` пока не записывает первый snapshot. Конечное состояние сохраняется. Эта копия сохраняет исходное поведение скрипта.

## Архивное поведение и ограничения переноса

Скрипты являются точными копиями исполнявшегося исходного кода, а не переработанным переносимым интерфейсом; соответствие путей и SHA-256 указано в `COPY-MANIFEST.tsv`. Некоторые скрипты записывают собственную копию в каталог результата или вычисляют её hash. Перед воспроизведением нужны точные Git checkout Core и Runner с ревизиями соответствующего опыта: скрипты получают Git identity через путь реально загруженного пакета. `fd-map/one_fresh_fd_map_v3.jl` дополнительно требует чистый checkout Core. Один номер версии пакета не задаёт эту identity. Точный native Project и Manifest runtime включены в `environment/runtime/`; для воспроизведения также нужны соответствующие checkout, зависимости и данные. Набор не подтверждает совпадение результата.

Относительные пути входов исходно привязаны к `.build/campaign133`: warm TOML ожидают `raw/S01-fixedU32/state.h5` относительно каталога TOML; oracle разрешает свои пути относительно `.build/campaign133`. Файл FD map исходно расположен в `.build/campaign133/fd-map/input.toml`, его пути разрешаются относительно этого каталога. Полные исходные HDF5 и identity сюда не включены; выбранные marker CSV и итоговые marker TOML приведены в `evidence/`, а исходные входы скопированы в `inputs/`. `frozen-spectrum/frozen_spectrum.jl` дополнительно требует `frozen-spectrum/source-input.toml` и конкретный hash state; `adaptive-frozen/adaptive_frozen.jl` требует результат `frozen-spectrum/integrals.h5` и пакет QuadGK. Восстановление layout без этих отдельных исходных артефактов недостаточно для запуска. Часть скриптов пишет файлы рядом с собой; используйте отдельный рабочий каталог, чтобы сохранить исходные свидетельства.

## REPLAY: восстановление layout

В отдельном checkout superproject, из его корня, при отсутствии `.build/campaign133` можно восстановить только опубликованные файлы следующими командами. Они не загружают данные VM и не выполняют расчёт. Пакет research должен быть доступен по указанному пути. Не выполняйте команды поверх существующих данных кампании.

```sh
bundle=components/qcl-negf-research/experiments/campaign133
work=.build/campaign133
mkdir -p "$work" "$work/oracle" "$work/frozen-spectrum" "$work/adaptive-frozen" "$work/fd-map" "$work/environment/runtime"
cp "$bundle/run_inner_v1.jl" "$work/run_inner-v1.jl"
cp "$bundle/run_inner_markers_v2.jl" "$work/run_inner_markers.jl"
cp "$bundle/run_inner_warm_v4.jl" "$bundle/diagnose_spectrum_v3.jl" "$bundle/read_markers.jl" "$work/"
cp "$bundle/validation/"*.jl "$work/"
cp "$bundle/inputs/"*.toml "$work/"
cp "$bundle/oracle/"* "$work/oracle/"
cp "$bundle/frozen-spectrum/"*.jl "$work/frozen-spectrum/"
cp "$bundle/adaptive-frozen/"*.jl "$work/adaptive-frozen/"
cp "$bundle/fd-map/"* "$work/fd-map/"
cp "$bundle/environment/runtime/"*.toml "$work/environment/runtime/"
```

В частности, validation-скрипты возвращаются в корень `.build/campaign133`, где они исходно находились; публичная папка `validation/` служит только для организации набора. Этот блок восстанавливает исходную часть набора; для дополнительных материалов `candidates/` исходные пути приведены в `COPY-MANIFEST.tsv`, а входы и условия запуска — в соответствующих протоколах. До отдельного запуска нужно восстановить необходимые исходные артефакты из VM, проверить их identity и SHA, подготовить активную среду Pkg и выбрать новые выходные каталоги. Некоторые скрипты требуют один поток Julia и BLAS или отказываются перезаписывать существующий выход. Новое исполнение — отдельный опыт; скопированные файлы сами по себе не являются его результатом.

## Малые свидетельства и график

`evidence/` содержит выбранные исходные CSV и TOML трёх запусков без массивов и файлов identity. `plots/plot_residuals.py` читает только их `history.csv` и строит две панели исходных `r_K` и `r_Σ` на общих пределах с линией `1e-8`. Его можно запустить отдельно с установленным Matplotlib, передав путь выходного PNG; рендеринг выполнен отдельно: журнал VM `.build/campaign133/environment/plotting-render.log` зафиксировал exit 0 и в публичный набор не включён; полученный `plots/warm-residuals.png` включён в набор. По умолчанию изображены только два warm-запуска: ось x — номер вычисления карты внутри каждого из них (1–64), счётчики сброшены. Холодный fixed U на 32 вычисления сохранён в CSV и не показан на графике. Первая точка warm unmodified повторно вычисляет границу исходного состояния; это не дополнительная независимая исходная итерация. Научный вывод по графику остаётся открытым.

`environment/runtime/` содержит точные Project и Manifest опыта. Их относительные пути к Core/Runner разрешаются только при восстановлении приведённого layout superproject; сами checkout и depot в набор не включены.

`provenance/run-identities.toml` — ограниченная выборка полей identity и завершённых summary для трёх B0 и трёх S01 запусков; исходные identity на VM сохранены без изменений. Завершение записи не означает сходимость.

## Кандидаты дополнительных материалов

Точные архивные копии сохраняют также исходные окончания строк и пустые строки в конце файлов. Поэтому обычный `git diff --check` сообщает о CRLF в audit CSV и пустой строке в архивном `source.jl`; их байты сохранены для проверки SHA. Проверка новых авторских текстов и таблицы копирования проходит без этих архивных исключений.

Архивные IFR `.patch` сохранены побайтово, включая однопробельные строки контекста unified diff. Проверка staged whitespace исключает только эти две точные копии; остальные новые тексты проверены отдельно.

`candidates/` содержит малые текстовые материалы PI frozen control, direct static map, contour oracle, adjacent source analysis, Γ и continuation128. Это подготовка к независимой проверке и публикации, не приёмка. `pi-frozen-control/attempt01/public-summary-projection.toml` — проекция исходного summary без двух приватных абсолютных путей, не дословный оригинал. Происхождение остальных копий указано в COPY-MANIFEST.

Γ в каталогах `unexecuted-v1` и `unexecuted-v2-memory-refusal` — архивные неисполненные или отклонённые варианты; они не являются результатом активного Γ опыта. V1 small-check завершился ошибкой, V2-memory получил отказ по памяти; эти случаи нельзя считать успешными запусками. Для холодного Γ attempt02 опубликованы 16 map, attempt TOML и независимый review: ограниченный опыт завершён без сходимости, native unconstrained validation не выполнялась. Наличие summary continuation128 не означает сходимость. Исходные массивы, полные identity и активные результаты в набор не копировались.

Точные пути воспроизведения новых кандидатов, их источники и SHA перечислены в `COPY-MANIFEST.tsv`; сами файлы сохранены с исходными байтами. Summary декамации — отдельно отмеченная проекция без приватного `core_import_path`. Четыре adjacent-отчёта являются предложениями и анализом исходников; отдельный принятый IFR benchmark проверяет оператор, а не сходимость SCBA.

Независимый review декамации ограничен фиксированными Γ и квадратурой: occupied integral N слабо чувствителен к проверенному расширению границы, тогда как полный sampled A и интегральная матрица M остаются чувствительными; полная сходимость по A/M не установлена. Это не оценка непрерывного предела или допусков хвоста.

## Snapshot4: завершённые дополнительные опыты

В `candidates/` сохранены малые свидетельства continuation128 и affine32, residual support и frozen Cauchy с независимыми обзорами; перечень исходных путей и SHA — в COPY-MANIFEST. Для двух Γ-продолжений native validation не запускалась (`not_measured`), научная приёмка — `false`; уменьшение reduced residual не является сходимостью SCBA. Frozen Cauchy — ограниченная проверка, не доказательство экономии полного SCBA. Полная per-energy таблица residual support осталась на VM; включены top20 и perK. Cauchy summary — обозначенная проекция без приватного `core_import_path`. `positive-source-operator-plan.md` — отдельное предложение, не результат запуска или реализации.

Дополнительная [квалификация Matsubara-результатов](candidates/reviews/gamma-density-interpretability.md) отделяет вычисленный функционал и проверку частотного хвоста от непрерывной плотности. Связь с real-axis integral условна относительно эрмитовости Hamiltonian и причинности интерполированного источника; малые дефекты и устойчивые sampled inverses сами этого не доказывают. Наличие верхнеполуплоскостных полюсов в наших данных также не установлено. По этой причине новый density run на Γ128 отложен; уже сохранённые численные значения остаются свидетельствами вычисленного функционала.

Stable-source Jv включает пять Φ и четыре Jv; derivative evidence ограничено проверенными направлениями. Final root pair проверяет фактические локальные checkout и direct HDF5 round-trip, не Runner checkpoint и не научную приёмку. Публичная log projection содержит только выбранные поля и SHA полных приватных логов.

Matsubara all5 — конечное N, фиксированный μ, direct static и LO raw solution; результаты обоих N относятся к сохранённым итерациям 11–16, хвосты и N-constraint не приняты, native pass отсутствует. На итерации 2 была отрицательная плотность, поэтому Pauli на всех итерациях не заявляется. Исходный первый `9b18` вариант сохранён на VM как неиспользованный; `finite-N-contraction.md` — условный математический анализ, не машинное доказательство. Активные M3 moments, μ-root, endpoint и current сюда не включены.

## Snapshot8: конечные Matsubara-контроли

M3 V1 завершился timeout с частичным N128; V2 завершён с BLAS1 и независимым review. Endpoint V1 остаётся невыполненным, V2 — отдельный проверенный контроль. μ-root refined V1 завершился технической world-age ошибкой до модели и карт; V2 — отдельная identity с конечными N=512/1024 и 112 map records. Сохранены входы, малые записи и независимые статические/value проверки; raw HDF5, identity и журналы не включены. Старые варианты μ128/256 не запускались.

Эти результаты относятся к конечному N, U=0, ALL5 direct static, full-line LO и заданному reference-tail/M3 численному варианту. Проверки заряда и свидетелей относятся к указанным записям и допускам; они не принимают исходный native baseline, Poisson, предел N→∞, базис/k или эксперимент. Mixed-axis brief — предложение, bond-current feasibility — невыполненная оценка.

## Postboot: native finite-bias evidence

Основной срок кампании — 16 ноября 2026, 17:00 Минск; это описание существующих результатов, не разрешение нового запуска. `postboot/` содержит малые свидетельства native ALL5 без e–e при фиксированном U: coarse 0/1 mV завершён по 32 карты на case, оба результата unresolved; fine48001 прерван пользователем и не содержит принятой matched пары; warm128 завершён по 128 вычислений на case, включая первое повторение границы (127 новых), оба unresolved. Это не принятие I–V или сходимости. FD-seed план будущий и здесь не представлен как результат.

Эти научные опыты используют Core e171; принятый Core db26 имеет отдельную source identity и не присваивается им задним числом. Research PR13 — отдельный незамердженный backup, он не является принятой базой этого каталога. Научные и производительные заметки — ограниченные hypotheses/reviews, не новые проверки всего solver.

Три driver опубликованы как проекции: приватная абсолютная строка BASE заменена относительной; исходный и публичный SHA и проверка обратного восстановления приведены в `POSTBOOT-PROJECTION-LEDGER.tsv`. Для исполнения отдельно необходимы исходные helper файлы, среда и данные; публичный относительный путь сам по себе не гарантирует воспроизводимое разрешение. Другие добавленные файлы сохранены побайтно.
