# Воспроизведение транспорта и граница доступности

В пакете есть [физический паспорт](device.toml), численные TOML-варианты, [генерирующий драйвер](run.jl), авторские адаптеры базиса и компактные скалярные свидетельства. По данным публикации транспортная приёмка не установлена. Все опубликованные токи диагностические; одноразовый отклик Hartree не является связанной петлёй Poisson–SCBA.

Генерирующий код требует Julia1.13.4, [Core e171](https://github.com/Afonenko-QCL-NEGF/QCLNEGF.jl/tree/e171caa60cce676c6c4238dd671e7c527f2bd977), Unitful, HDF5 и остальные зависимости Core. Архивный driver проверяет точные Core/tree и runtime Manifest SHA. Runtime Manifest, depot и установленные библиотеки здесь не распространяются. Поэтому этот Git-набор не объявлен автономным повтором первоначальной среды. Новый расчёт требует подготовленного совместимого окружения и отдельного выходного каталога; он будет новым опытом.

Из корня экспериментального каталога предварительный просмотр и самостоятельный cold запуск имеют вид:

```sh
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
julia --startup-file=no --threads=12 --project=/path/to/pinned-environment transport/run.jl --plan transport/native54-03.toml
julia --startup-file=no --threads=12 --project=/path/to/pinned-environment transport/run.jl transport/native54-03.toml /path/to/new-native-output
```

Эти команды приведены для документирования, при упаковке они не выполнялись. Для warm вариантов `warm_attempt` задан именем соседней исходной попытки; public projection драйвера разрешает его относительно TOML. Исходный согласованный checkpoint должен быть отдельно восстановлен с указанными SHA либо заново создан точным predecessor driver. Наличие `summary.toml` без `state.h5` недостаточно. Модель проверяет совместимость профилей, сетки, базиса, U и физического fingerprint; первая warm карта дополнительно проверяет исходные скаляры. Публичные адаптеры используются из соседних `cell-basis/` и `cell-basis-refinement/`; изменения пути отражены в PUBLIC-PROJECTION.json, численные формулы не изменены.

`history-selected.csv` намеренно содержит только начальные карты, заявленные checkpoints и последние16 строк. Это не полная история для повторной статистики. Агрегаты `baseline-summary.json`, `warm-alpha-comparison.json`, `compact-basis-comparison.json`, `compact-window-comparison.json`, `wide-rank9-summary.json` и `long-summary.json` сохраняют выводы по полным исходным сериям. Непрерывная native цепочка содержит **910 различных состояний:128+16+768−2 повторённые стартовые карты**. Отдельные compact и альтернативные ветви в это число не входят.

Скрипты `summarize.py`, `summarize_long.py` и `compare_*.py` требуют полного исходного ledger и некоторых excluded metadata; опубликованные selected CSV не должны подставляться вместо полной истории. Эти файлы включены как порождающие определения агрегатов. Для точного повтора предоставьте полный архив либо выполните соответствующие генерирующие drivers заново, затем вызовите скрипты из каталога transport. Некоторые скрипты записывают JSON рядом с собой; используйте отдельную рабочую копию.

[Независимый audit](audit_saved_density.jl) читает согласованные `model.h5`, `state.h5`, summary/resolved и при необходимости родительские данные. Он вычисляет спектральную сумму и J(z) по одному k-срезу. Большие HDF5 и сырые матрицы в Git не включены. Их hashes приведены в сводках; hashes обеспечивают проверку предоставленного файла, но не создают отсутствующие данные. Терминальные JSON исключают сырую матрицу плотности, сохраняя наблюдаемые токи и signed balances.
