# Передача основного научного анализа на кластер

Научная цель проекта — получить воспроизводимый стационарный транспорт и установить чувствительность результата к представлению и квадратурам. Ближайшая задача на кластере — прочитать собственные первичные данные Dupont V843 и выбрать следующий опыт на основании двух разных наблюдений: дефекта переноса между периодами и спектральной ошибки при том же размере базиса. Для Fath целевая точка остаётся 54 мВ на период. Ночная точка V843 имеет поле 21 кВ/см, падение 75,936 мВ на период, температуру 50 К и нулевой Хартри. [Постановка V843](../../README.md) · [Снимок Fath на общей Q28](https://github.com/Afonenko-QCL-NEGF/qcl-negf/blob/d76b588c1af2ef5d3a4b09b67d0094a9a809db11/studies/fath54-common-q/README.md)

## Почему закончилась ночь

Основной DAG 173 шёл с 19:41:35 до 20:07:31 по Минску. Он вернул 75 измерений и шесть технических отказов F. В DAG 206 эти шесть исходных конфигураций пересчитали с исправлением записи π в TOML. Восстановление заняло 4 мин 21 с внутри времени основного запуска. Всего прошло **25 мин 56 с**, получен **81 уникальный результат из 81**. Опубликованная правка меняет одну строку сериализации после вычисления спектров. [Квитанции и времена UTC](run-receipt.json) · [Исправление Флоке](https://github.com/Afonenko-QCL-NEGF/qcl-negf/commit/87b3e4dd48ad59d29df2319fb0eef5b0921f2020)

Очередь содержала конечные одношаговые диагностики. Даже у расширенных H и G медианное время вычислительной фазы Julia составило 78,3 и 87,0 с. Были доступны восемь машин и 218 логических CPU. Для 20 успешных задач на Linux медиана отношения фактического процессорного времени Julia к произведению времени выполнения на выделенные CPU равна 18,7%. Для 61 успешной задачи Windows сопоставимого измерения Julia нет. Это объясняет, как удалось быстро исчерпать программу, и оставляет открытым вопрос об оптимальном числе потоков. Длительность будущей программы стоит оценивать по времени представительных задач каждого семейства и числу доступных машин. [Ресурсы и границы измерений](run-receipt.json)

## Первое чтение на площадке

1. На менеджере найти приватный каталог, содержащий основной manifest.json и подкаталог recovery-floquet-87b3e4d. Опубликованный научный вход имеет ревизию 40401ba7f6a27ca22e20961e50d1881eac08f3b1, восстановление F — 87b3e4dd48ad59d29df2319fb0eef5b0921f2020, результаты — 5d25ec0fab9c7801e5aeeeaeec28897246a285cb. Зафиксировать SHA Manifest Julia и закреплённое дерево Core из квитанции. Необходимые архивы находятся на менеджере по относительным локаторам. [Квитанции](run-receipt.json)
2. Из корня переданного checkout выполнить команду ниже, подставив фактический путь. Она читает файлы и сверяет опубликованные SHA-256. При расхождении указать конкретный путь и попытку. Представленная здесь сверка проведена по опубликованным JSON и правке сериализации. Независимое чтение приватных первичных данных предстоит выполнить на кластере. [Инструмент сверки](verify_archive.py)

   ```sh
   python3 studies/v843-overnight-front/evidence/run-173/verify_archive.py "$PRIVATE_CAMPAIGN_ROOT"
   ```

3. Для независимого чтения дать проверяющему условия, критерии и TOML двух рангов B11. Из пар H извлечь обе стороны на общем k и отдельно максимумы по всем k. Для G пересчитать интеграл модуля разности двух кривых фиксированного гауссова зонда, нормированный на интеграл координатной кривой. Повторить по полной сетке и через один узел. Первое заключение записать до сопоставления с выводом ведущего. Для I взять I_K17_Z288 и I_K65_Z288, для F — восстановленный F_N9_Z288. Отметить, какие величины удалось пересчитать из сохранённых массивов, а какие доступны как готовые измерения. [Локаторы, поля и единицы](summary.json) · [Методика свидетельств](../../../../docs/research-archive/methods.md)
4. При совпадении первичных данных первым предложить опыт на фиксированном подпространстве H и отдельно контроль на полном примесном Q. Если остаток H на фиксированных физических зондах убывает до погрешности, а полноблочный растёт с рангом, это поддержит вклад добавленного сектора. Если остаток сохраняется на тех же зондах при малом контроле чистого переноса, исследовать выбор или локализацию подпространства. Кандидат, наблюдаемая, допуск, численная неопределённость, альтернативный прогноз и неопределённый исход фиксируются до вычислений. Старт следующей очереди — отдельное поручение пользователя.

## Подготовка чата и репозитория

Чат без проекта подготавливает checkout qcl-negf на менеджере и выводит путь, который нужно открыть как проект. Проверенная версия main с принятым комплектом — 1f20dc7b029782871933caad8e4b0fd7f0e0410a. В ней и в ревизии результатов присутствуют qcl-freeze-experiment и qcl-recompute-from-inputs. Первый фиксирует физический план, версии и критерии проверки. Второй восстанавливает расчёт из опубликованных входов, когда архив неполон. Внутренние ссылки обоих разрешаются относительно репозитория. Для обновления достаточно актуального проектного checkout с этими каталогами и исходными docs и runner. При локальных изменениях или занятой рабочей копии выбрать отдельный worktree. Старые четыре проектных навыка были удалены в принятой работе. Общие пользовательские навыки остаются самостоятельной областью. Sol может повышать усилие до ultra для согласованного сложного рефакторинга. Для Astra high остаётся одна консультация после двух различающих физических опытов с противоречивыми исходами и сверки их условий.
