# V843. Ночная кампания по базису, спектру и угловой квадратуре

Цель — определить, какую численную правку имеет смысл переносить в транспортный решатель. В DAG 154 сдвиг координатного оператора прошёл, но соседние модовые блоки H(k) в полном окне дали относительное расхождение 4,765 × 10⁻⁴ при допуске 10⁻¹⁰. Два входа примесного оператора при 128 углах дали 4,056% и 4,824% при допуске 1%. RMS статического спектра полного B11 составил 1,843 мэВ. Транспортных карт было ноль. Сохраняем эти результаты как исходную точку и сравниваем объяснения ошибки по независимым наблюдаемым. ## Постановка и различающие прогнозы

Для полевой серии используется Dupont V843 при 21 кВ/см, то есть 75,936 мВ на период. Температура исходной постановки 50 К, Хартри равен нулю. Сглаживание η относится к конечному спектральному диагностическому опыту. F использует ту же послойную структуру при нулевом поле и кольцевой границе. В H и G в одночастичный гамильтониан входят одинаковые профили зоны и масс. Используемые способы задания доноров и экранирования различаются. При включении Хартри или рассеяния такое сравнение потребует унификации этих входов. Кольцо F использует одну конвенцию масс на гранях в двух сборках. Его совпадение ничего не измеряет о погрешности приближения непрерывной задачи. Двухточечные входы I дают локализацию угловой ошибки. Результаты прежнего действия примесного оператора на полном Q сохраняют собственный допуск. Наблюдаемые G относятся к конечной системе без рассеяния. ## Как читать результаты

Правила классификации фиксируются кодом до расчёта. Для H порог 10⁻¹⁰ используется вместе с контролем чистого переноса, для F — на нормированном расхождении отсортированных спектров. Для G рассчитываем относительную интегральную разность спектров фиксированного зонда по каждому k в диапазоне от −60 до 120 мэВ. Критерий 1% учитывает двукратное изменение этого показателя между полной и вложенной энергетическими сетками. Это оценка чувствительности к интегрированию. Для I принимаем решение при устойчивости сравнения 2048/4096 в пределах 0,1%. Сравниваем со своим эталоном и взвешенную ошибку действия, и худшую пару. [Точные правила и обработка неопределённостей](events.py)

В отчёте сверить пары, в которых менялся только один фактор. Сопоставлять G разных сеток по общим k при одинаковых окне, ранге и η. Отдельно сверить вложенные сетки по энергии. Улучшение лишь при увеличении η может быть результатом сглаживания. Проверять наличие явления и при меньшем η с достаточным энергетическим разрешением. Пики возле края энергетического окна помечать отдельно. Если H и G дают разные заключения, привести оба числа и назвать измерение, которое способно различить причины. Сотни индексов k и углов внутри одной конфигурации являются коррелированными измерениями.

## Подача на удалённом кластере

Использовать Linux-узел управления, штатный планировщик, фактический приватный инвентарь Linux/Windows и свободные места. Для упаковки нужен Python 3.11+ и чистый checkout этого коммита. На вычислительных узлах нужны рабочие Python и Julia 1.13.4. По умолчанию Julia инстанцирует закреплённый Manifest в доступном для записи depot. Для автономных узлов заранее подготовить совместимые кеши под каждую ОС и архитектуру, указать доступный сервисной учётной записи JULIA_DEPOT_PATH и QCL_INSTANTIATE=0 в настройках задания. Сначала подтвердить доступ к зависимостям и действительные пути для обеих ОС. Входы и исполнители четырёх серий приезжают в архиве из Git. Старые бинарные состояния отсутствуют в зависимостях.

Пример для нового приватного каталога на менеджере. Задать WORK и PACK абсолютными путями без пробелов, пути к интерпретаторам и PRIVATE_INVENTORY взять из рабочей конфигурации площадки. Локальные site-файлы проверить до отправки, включая Python, Julia, depot, квоты диска и памяти. Использовать выделяемую память после резерва ОС. Для крупных окон предварительно оценить пиковую память по размеру плотных матриц и данным площадки. Если подходящих узлов меньше, использовать пригодные и записать ограничение.

```sh
cd /path/to/checkout
front=studies/v843-overnight-front
python3 "$front/queue.py" --out "$WORK"
python3 "$front/batch.py" --work "$WORK" --out "$PACK" \
  --workers "$PRIVATE_INVENTORY" --commit HEAD --wave all-ready \
  --linux-python "$LINUX_PYTHON" --windows-python "$WINDOWS_PYTHON"
cd "$PACK"
condor_submit_dag campaign.dag
```

В all-ready ставится 81 задание. Первые 65 имеют повышенный приоритет, ещё 16 расширяют окно, сетку или передний сектор. У расписания нет общего научного предка. Каждая машина получает не более одного одновременно выполняющегося задания и все доступные слоту CPU. Привязка к машинам статическая, очередной блок меняет распределение семейств. При выпадении машины её незавершённые задания можно поставить на исправную с сохранением исходных ID и учётом первой попытки. H и F используют многопоточный BLAS. G распределяет независимые энергии по потокам Julia и переключает BLAS между плотной и параллельной фазами. I распределяет независимые радиальные расчёты по потокам Julia. Измерять фактические CPU time, wall time, ожидание, пиковую память и долю CPU по квитанциям и истории площадки там, где эти данные доступны. При насыщении памяти или малых размерах задач резерв CPU может превышать эффективное использование. После успешной постановки сохранить ID DAG, путь к результатам и завершить чат. Очередь и FINAL работают самостоятельно.

FINAL сохраняет валидированные завершённые TOML, receipts.json и снимок scientific-events/snapshot-*/events.json с правилами и ссылками на исходные данные. В comparisons.json рядом приведены пары завершённых опытов с одним изменённым параметром. Пропуски, технические сбои и научно неопределённые выводы учитываются раздельно. При необходимости восстановить сборку из возвращённых архивов командой `python3 batch.py collect --out "$PACK"` в пакете. Для публикации свести результаты по семействам, привести таблицу сопоставимых пар, диапазоны и худшие случаи с путями и хешами. Хранить на площадке полные спектры и журналы. В Git отправлять компактный итог и первичные числа для ключевых сравнений, без приватного инвентаря и чекпоинтов. Время завершения определяется измерениями на кластере.

## Условная транспортная ветвь

В каталоге описаны ещё 4 опыта C (действие пяти каналов на фиксированном входе) и 6 T (базис, построенный переносом). Исполнителей и автоматической отправки этих десяти опытов в этом пакете нет. Для их реализации нужны точные исходники операторов прежнего опыта или проверенная реализация в отдельном коммите и воспроизводимая сборка входов. Для изменённого базиса сохранять собственный ранг Q, операторы и хеши. Допуск MAP0 принимается по полному протоколу DAG 154 на **том же** кандидате, включая исходную проверку H(k), два исходных примесных входа, статику, все пять каналов, токовые сечения, источник и память. После подтверждённого допуска разрешена одна свежая карта с независимым чтением. Даже её успешное вычисление оставляет стационарность отдельным вопросом. [Граф и условие решения](queue.py)
