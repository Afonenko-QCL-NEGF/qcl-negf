# Текущий рабочий маршрут QCL-NEGF

Это указатель по опубликованным исходникам программы от 2026-10-27. Он не является отчётом об
установке, научной сходимости или доступности конкретного backend.

## Исследователь

Начните с [русского руководства Research](../components/qcl-negf-research/docs/researcher-guide.md):
цель, структура, гипотеза, граничные случаи, источники параметров и frozen plan предшествуют
запуску. [Конфигуратор Runner](../components/QCLNEGFRunner.jl/docs/src/user/configurator.md)
описывает используемые значения, origins и проверку конфигурации. Изменение CPU/RAM не должно менять
scattering, сетку, базис, энергетическое окно или допуски.

[Постановка S01](../components/qcl-negf-research/docs/equilibrium-s01.md) — отдельный научный этап.
Инженерная synthetic-проверка не заменяет SCBA/Poisson-сходимость, физические диагностики,
достаточность дискретизации или экспериментальную валидацию. Сравнение двух несошедшихся точек само
по себе не доказывает точность.

Для готовых данных используйте независимый [Results](../components/qcl-negf-results/README.md) и его
публичный API. Проверяйте source/model, run/attempt, полноту и выбранный state; отсутствующие данные
не равны нулю. Новый solve не является частью чтения или экспорта. Сохранённые карты, сравнение и
help должны проходить свои native и браузерные проверки; наличие руководства не подтверждает эти
gates.

## Разработчик

Единый цикл описан в [CONTRIBUTING](../CONTRIBUTING.md): owning change, проверка по влиянию,
независимое review, owning PR, затем опубликованный root gitlink и необходимые integration checks.
Физика и in-memory вычисления принадлежат Core; файлы и checkpoint — Runner; форматы — Contracts;
независимое чтение — Results. UI и scheduler не определяют научную приёмку.

[Impact checks](impact-checks.md) используют committed refs. Для незакоммиченного overlay отдельно
зафиксируйте состав; не выдавайте clean published source за произвольный рабочий каталог. D —
текст/ссылки/формат; L — локальное поведение; N — реальный пакет/service/backend; S — отдельно
порученный научный опыт. План проверки и exit code не заменяют содержание результата. Повторяйте
необходимые проверки после влияющего изменения или открытого failure.

[Совместимость depot](depot-compatibility.md) отделяет исходное producer-свидетельство от текущего
consumer graph. При доказанной совместимости сохраняется оригинальная identity; новый source не
переписывает старый receipt. [Сборка документации](cached-documentation.md) использует один обычный
Nix artifact для трёх owning page graphs. Source-unit inputs и полная сборка имеют разные входы и
отдельные проверки. Русское руководство Research доступно по ссылке выше; его включение в локальную
доставку help/manual проверяется отдельно.

## Оператор

[Single-server runbook](single-server-deployment.md) задаёт дешёвый preflight четырёх NixOS roles и
строгую проверку фактического nginx до тяжёлого bootstrap.
[Инфраструктурное руководство Platform](../components/qcl-negf-platform/docs/infrastructure.md)
описывает owning backends. Реальные адреса, private inventory, credentials, диски, receipts и
научные данные хранятся вне публичного Git.

[Восстановление](public/operator-recovery.md), [runtime захвата](capture-runtime-delivery.md) и
[свидетельство solver](solver-build-receipt.md) описывают отдельные границы provenance и доставки.
До mutation установите владельца VM/job/storage; неизвестное владение блокирует именно затронутое
разрушительное действие. Сначала сверяйте исход операции с потерянным ответом, затем продолжайте; не
повторяйте install, merge, cancel или удаление вслепую.

Перед первым прерыванием старого расчёта программа требует свежую read-only оценку R00 на целевом
ноутбуке. Старые результаты, массивы, history и checkpoint не экспортируются и не сохраняются.
Разработка независимых частей продолжается. Последующая установка требует отдельных build,
trust/staging, service, boot, synthetic job/cancel/fault/restore и browser свидетельств. Новый
научный запуск остаётся следующим отдельным этапом.

## Продолжение программы

[Исполнительный план](implementation/codex-execution-2026-10-27.md) определяет полномочия, routing
Sol/Terra и граф P01–P32. [Спецификация](implementation/project-simplification-2026-10-27.md) задаёт
назначение задач. Исторические отчёты сохраняют контекст своих source и attempts; их статусы не
переносятся автоматически на текущий состав.

При обрыве связи сохраните компактное operational state и operation IDs, защитите чужие ресурсы,
после восстановления сверяйте Git/receipts/remote state до повторения изменений. Связь с VM,
работающий процесс, сходимость и физическая приёмка — разные наблюдения. Расписание не гарантирует
работу выключенного ноутбука или приложения.
