### 3.2 Reuse, reproducibility и новый release

1. **Engineering reuse native output** разрешим только при same resolved drv/output identity, verified contents и identical **native test contract** с оригинальным positive execution evidence. Source distinction сохраняется: новый root может ссылаться на unchanged native derivation, не переписывая original producer/root или failed logs. Обязательно отдельное comparison receipt с original evidence locator; отсутствие хотя бы одного звена = `reuse unknown`, не pass.
2. **Same bytes** — только наблюдение о content digest; same bytes без same native test contract не переносит suite acceptance. Изменённые factory/patch/phases/profile/worker limit/selected suite лишают применимости старый contract proof, даже если runtime package version совпадает.
3. **Reproducible build** требует отдельных сравнимых build receipts по M07 и own finite grant. Один cached output, prefetch, два имени одного path или совпавшие declarative hashes не доказывают reproducibility. Два новых rebuild здесь не разрешены.
4. **Full release нового root** требует final ready source freeze, опубликованных owning refs/gitlinks, required native/backend/restore gates и sole final CI bound to exact final head. Reuse не закрывает final source checks, installed services, cold boot, backups, recipient delivery, scientific criteria. G1 public release не разрешает.

## 4. Cache URI: существующая policy без новой trust политики

Существующий нормативный текст `P/docs/application-cd.md:46–50`: непустой transport route без whitespace/control/leading dash/**embedded password**; credentials вне URI/manifest; ordinary Nix signature/trust checks сохранены. Код TS (`ops/application_cd.ts:21–33`) и Python (`P/...:1064–1073`) проверяет password, **не запрещает username**. `TARGET` и реальные copy routes `ssh-ng://admin@worker.invalid` (`P/...:39,2805`) содержат SSH account username. Plain `ssh://user@host`/`ssh-ng://user@host` — transport account selector, не автоматическое признание нового credential/trust scope. Поэтому blanket запрет любого `@`/`username` неверен и ломает существующий Nix SSH route.

Есть конкретное расхождение: TS проверяет truthiness `URL.password`, поэтому явный пустой password delimiter в `https://user:@cache.invalid` проходит его check; Python `.password is not None` отвергает. Оно исправляется source-only T2 ниже. Непустые passwords reject в обоих; URI parse error должен быть rejection до native commands.

Не заявлять по этим checks универсальное распознавание secrets в userinfo/query/path. Произвольная token-строка в позиции username неотличима от account identifier; query secret тоже не распознаётся. Existing policy запрещает помещать secret bytes в manifest; review/build admission проверяют отсутствие credentials в публикуемом artifact без вывода самих bytes. Новый scheme allowlist, запрет HTTP username, secret-query словарь, автоматическая key rotation или новая аутентификация **не вводятся этим D**. Если требуется более сильная машинная credential-free policy, нужен отдельный explicit owning D: текущая доказанная гарантия называется password/argument guard, а не secret scanner. Для depot generation HTTP(S) `ops/solver.ts:142–147` уже rejects username и password; этот отдельный контракт не переносить на Nix SSH cache.

Это не подмена actual pinned Git sources, но inaccurate provenance manifest. Nix checks защищают format/Julia/Manifest, но не entire graph. Не выдавать это за доказанный runtime exploit.

**Paths:** `ops/solver.ts`, `tests/solver_test.ts`; caller `ops/application_cd.ts` передаёт already-derived expected graph. Не менять graph source authority или schema, Git semantics, dependency pins, archive extraction или physics. Pure validator принимает `(spec, expectedGraph, expectedJuliaManifestSha256)` и возвращает validated spec либо throws. Оба CLI consumers вызывают его **до prefetch/build**. Проверяются depot format=`qcl-negf.julia-depot.v1`, Julia=`1.13.0`, exact `juliaManifest`, graph format/root и полный набор `(path, revision, url)` expected graph. Object key order несущественен; components сравниваются по path после reject duplicate paths, порядок списка несущественен. Missing/extra entries и изменённые values reject. Preserve existing buildSolver revision defense. Expected Manifest SHA получают существующим checksum path; это не вручную записанный constant. Новой URL scheme policy, secret scanner и archive hash policy этот ticket не добавляет. Metadata fields остаются produced by native generator. Invalid bound metadata never schedules `nix`.

**Positive fixtures:** original generated-shaped metadata with exact graph/lock identities; graph field order handled по declared object contract; same archive bytes at allowed mirror route не подменяет source identity; valid file prefetch then build; valid HTTPS direct build.

**Negative fixtures:** same root revision, wrong component commit/url/path; missing/extra/duplicate components, wrong graph format/root; missing/wrong depot format/Julia/Manifest hash; absent/wrong root revision; existing wrong revision case still no commands. Existing hash-prefetch rejection remains separate and unchanged. Expected: before first execute callback, not only later Nix fail. Production guard keeps clean checked-out graph checks; fixture doesn't read/import solver.

**Gate/budget:** root CP-CODE после source review + targeted root Deno fixtures in prepared environment. At most **one** admitted Deno invocation≤120s, 2CPU/4GiB/output≤2MiB; no install/Nix/Julia/network, fake execute callbacks. Shared L-DENO counters coordinator-owned, не новый дополнительный grant.
