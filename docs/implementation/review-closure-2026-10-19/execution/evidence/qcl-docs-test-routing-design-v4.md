## R1. Один зарегистрированный producer, известный извне source closure

Выбран единственный private producer `RootDocsSetupV1` — функция `setup_main` в Root `ops/docs_tests_native.py`. Он не выбирается descriptor field/schema/plugin. В native code фиксированы producer ID `root-docs-setup-v1`, protocol version1, exact Python functions и exact record readers ниже. Другие producer IDs/versions отклоняются. Это software registration выбранного code path, **не** новый trust root.

Единственное основание доверия producer — **уже доверенный active Root/operator/CI harness parent**, который имеет явное поручение на этот attempt и запускает проверенные Python/runtime/source bytes. Parent задаёт expected hashes/bootstrap/runtime ownership/deadline **в памяти при exec**, до запуска repo code; record из source tree или descriptor не может их установить. Родительский существующий trust boundary не заменяется `getuid`, filename, native16 closure или self-hash. Если данный installation ещё не имеет такого trusted launch parent/runner wrapper с execution grant, это точный irreducible operator prerequisite, а не необходимость нового public trust registry. D4 не выдаёт такой grant и не устанавливает wrapper.

Root обязан подтвердить этот handoff при будущем исполнении. Ни метаданные этого D4, ни source-level fake не создают active parent. На нынешнем сервере CI key unconfirmed и control/compute NoRoute не дают права считать CI wrapper существующим. Это отсутствие actual integration/operator handoff; локальный интерфейс реализации ниже полностью задан и не требует угадывать его semantics.

### Точный constructor на стороне trusted parent

```python
start_docs_setup(*,
  scope,                    # 'prerequisites-only'|'docs-units-only'|'full-root-check'
  setup_id,                 # fresh 128-bit lowercase hex, generated by parent
  authorization_ref,        # already accepted Root execution record ref, audit only
  input_ref,                # descriptor exact path/SHA; <=32768B
  expected_source,          # Root HEAD, exact8 graph; expected native16 path/blob/SHA
  bootstrap,                # exact Python executable+runtime closure+native.py hashes
  expected_tools,           # exact path/hash/version for deno,node,python,Git
  existing_observations,    # refs produced by RootDocsSetupV1, or None
  resources,                # live delegated cgroup binding + explicit control reserve
  storage,                  # owned roots/cache/raw/protocol total caps
  allowed_phases,           # exactly one docs-preflight then optionally one full/docs
  wall_deadline_utc,         # finite; no future capture timestamp acceptance
  monotonic_deadline,       # absolute, supplied by same active parent clock
  execute_grant,            # nonserializable parent-owned object, not input JSON

```

`execute_grant` является уже существующим capability/decision внутри доверенного harness parent; не `True` и не текстом `READY` от caller. Constructor проверяет parent action scope/attempt/limits соответствуют grant и открывает private duplex control channel через `socketpair(AF_UNIX,SOCK_STREAM)` (далее control pipe). Его единственный child FD передаётся непосредственно setup Python через `pass_fds`, только этот one-time bootstrap child; channel не проходит через Deno tasks. Перед first repo execution parent связывает producer source hash с своим expected bytes, interpreter hash/runtime closure с заранее доверенным inventory и exact executable path. Source16 record дополнительно проверяет code composition, но **не** удостоверяет tool refs/parent authority — graph/tool assertions нельзя самоподписать совпадающим SHA.

`allowed_phases` — finite ordered entries `{phase:'preflight'|'check'|'docs', attempt:<unique literal>, input_sha256, source_head, not_after_utc}`; scopes cannot escalate. Full workflow разрешает preflight+check, docs-only preflight+docs. Direct check разрешает один check с тем же internal preflight; необязательный внешний preflight не необходим. Targeted ops/ci scopes не создают docs capability. No execute_grant/parent pipe ⇒ implementation does not construct RunningDocsSetup, no child. Валидный admitted constructor содержит обычный executable code path и может дойти до actual executor; permanent blocked stub запрещён.

### Active parent pipe и broker: точный lifecycle через task boundaries

После native metadata/resource validation trusted parent посылает по control pipe **один** bounded≤131072B startup frame с exact constructor data и fresh256-bit random setup nonce. Frame — transport от уже известного parent, не файл от CLI. Native setup ACK связывает nonce, setup_id, expected source/input/native bytes, scope, собственные pid/startticks/uid и active monotonic deadline; parent сверяет их с закреплённым pidfd before-go gate. Setup не читает argv JSON как grant. EOF/malformed/extra frame до ACK⇒refuse. После ACK pipe остаётся открытым до terminal receipt; parent EOF/cancel byte⇒owned cancellation всех clients/driver/Git/units. Completion ACK закрывает setup lifecycle. Никакого повторного использования setup_id и old nonce.

Setup создаёт `AF_UNIX SOCK_STREAM` broker socket в fresh0700 control dir, socket0600. Parent получает endpoint и **отдельный random256-bit one-phase token** для каждой allowed phase; server хранит token→exact phase/input/source/attempt/deadline в памяти. JSON receipt содержит token hash, сами tokens не сохраняются в raw/log/receipt. Endpoint сам по себе не даёт authority. SO_PEERCRED uid + exact requester /proc birth/ancestry сверяются с известным trusted launch subtree (parent pins task/ops-ci leader pidfd). Одна private Unix connection имеет≤64KiB hello/request, bounded read deadline; no unknown command or arbitrary executable. Same-uid hostile process/ptrace/environment theft исключены уже существующей trusted local harness premise; этот protocol не заявляется multi-tenant boundary.

Client hello exact keys `{version:1,setup_id,phase,attempt,input_sha256,source_head,token,client_pid,client_startticks}`. Server сравнивает с live in-memory phase record и peer identity; token constant-time compare, uses once: RESERVED до проверки input, CONSUMED перед dispatch gate, никогда не возвращается в available после failure. Повторный concurrent/replayed phase, root/input mismatch, stale deadline, unknown peer, parent EOF⇒refuse/retain; не расширяют grants. Client получает `{kind:'accepted',request_id,setup_nonce_digest,scope,binding_digest}` либо typed refusal; data pipe ограничена D3 protocol caps. Удаление/copy handoff JSON/смена filename не может создать phase record. Broker only ops: `preflight`, `check`, `docs`; privileged `execute arbitrary argv`, version probes, bootstrap/prepare/deploy APIs отсутствуют.

### Bootstrap ownership/resource/capture order

До first driver/Git child trusted parent уже держит active deadline, control reserve и process ownership. Startup protocol:

1. 2. Stub code belongs to already reviewed trusted parent, not newly imported arbitrary repo module; failure to support this gate blocks launch. 3. Setup starts exact Python isolated lifecycle; native driver и все child supervisors/Git descendants входят в тот же bounded workload ownership/cgroup **до dispatch**. Parent continuously bounded-drains setup stdout/stderr/protocol, holds cancellation pipe and monotonic watchdog; driver OOM/EOF cannot erase originals. 4. Only after active guard membership/limits+ACK source binding reader may dispatch first Git. Every Git is launched through `execute_bounded(command,kind='source-git',...)`, using the same nonblocking retained byte drains/owner/cancellation/terminal-empty API as D3 unit executor. NUL is expected and preserved only for owning `ls-tree -rz/-z` framing; never reject valid Git NUL delimiters or apply descriptor NUL rules to that stream. Driver no-go, protocol inactivity/deadline, parent EOF, stale source, any guard/drain/capture error ⇒ cancel descendants+retain all prior captures. No next unit.

Native workload boundary начинается до первого repo child; all native launcher/driver/Git processes accounted with outer control reserve.
