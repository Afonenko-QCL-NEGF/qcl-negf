### 3.2 Reuse, reproducibility и новый release

1. **Engineering reuse native output** разрешим только при same resolved drv/output identity, verified contents и identical **native test contract** с оригинальным positive execution evidence. Source distinction сохраняется: новый root может ссылаться на unchanged native derivation, не переписывая original producer/root или failed logs. Обязательно отдельное comparison receipt с original evidence locator; отсутствие хотя бы одного звена = `reuse unknown`, не pass.
2. **Same bytes** — только наблюдение о content digest; same bytes без same native test contract не переносит suite acceptance. Изменённые factory/patch/phases/profile/worker limit/selected suite лишают применимости старый contract proof, даже если runtime package version совпадает.
3. **Reproducible build** требует отдельных сравнимых build receipts по M07 и own finite grant. Один cached output, prefetch, два имени одного path или совпавшие declarative hashes не доказывают reproducibility. Два новых rebuild здесь не разрешены.
4. **Full release нового root** требует final ready source freeze, опубликованных owning refs/gitlinks, required native/backend/restore gates и sole final CI bound to exact final head. Reuse не закрывает final source checks, installed services, cold boot, backups, recipient delivery, scientific criteria. G1 public release не разрешает.

## 4. Cache URI: существующая policy без новой trust политики

Существующий нормативный текст `P/docs/application-cd.md:46–50`: непустой transport route без whitespace/control/leading dash/**embedded password**; credentials вне URI/manifest; ordinary Nix signature/trust checks сохранены. Код TS (`ops/application_cd.ts:21–33`) и Python (`P/...:1064–1073`) проверяет password, **не запрещает username**. `TARGET` и реальные copy routes `ssh-ng://admin@worker.invalid` (`P/...:39,2805`) содержат SSH account username. Plain `ssh://user@host`/`ssh-ng://user@host` — transport account selector, не автоматическое признание нового credential/trust scope. Поэтому blanket запрет любого `@`/`username` неверен и ломает существующий Nix SSH route.

Есть конкретное расхождение: TS проверяет truthiness `URL.password`, поэтому явный пустой password delimiter в `https://user:@cache.invalid` проходит его check; Python `.password is not None` отвергает. Оно исправляется source-only T2 ниже. Непустые passwords reject в обоих; URI parse error должен быть rejection до native commands.

Не заявлять по этим checks универсальное распознавание secrets в userinfo/query/path. Произвольная token-строка в позиции username неотличима от account identifier; query secret тоже не распознаётся. Existing policy запрещает помещать secret bytes в manifest; review/build admission проверяют отсутствие credentials в публикуемом artifact без вывода самих bytes. Новый scheme allowlist, запрет HTTP username, secret-query словарь, автоматическая key rotation или новая аутентификация **не вводятся этим D**. Если требуется более сильная машинная credential-free policy, нужен отдельный explicit owning D: текущая доказанная гарантия называется password/argument guard, а не secret scanner. Для depot generation HTTP(S) `ops/solver.ts:142–147` уже rejects username и password; этот отдельный контракт не переносить на Nix SSH cache.

## 5. Минимальные source-only implementation tickets после CP-DESIGN

Это готовые предложения owning I medium, а не сделанные edits. Coordinator сериализует shared Platform file writer. Independent high R получает immutable source, требование и fixtures до авторского диагноза. Никаких target imports/checks этого D не исполнялось.

### T1 — Root: один authoritative metadata input, exact consumed bytes и graph binding

**Причина / F1:** нынешний `buildSolver(spec, revision, target, ...)` имеет два независимых depot inputs. Prefetch использует `spec.url/hash`, а Nix заново читает `target`; `spec=A`, `target=B` может валидировать один object и потреблять другой graph/archive metadata. CLI pathname replacement после первого parse — та же незакрытая edge. Revision-only check и Nix format/Julia/Manifest guards не сравнивают весь graph. Это не доказанный scientific/runtime exploit, а exact provenance/consumed-input gap.

**Owning paths:** `ops/solver.ts`, `ops/application_cd.ts`, `nix/solver.nix`, `tests/solver_test.ts`; `tests/application_cd_test.ts` только relevant assembly-before-command control. Caller usage search на selected source нашёл два operational TS callers (`solver.ts`, `application_cd.ts`) и root solver tests. Separate `nix/local-lab-packages.nix::input.depotManifest` не вызывает этот entrypoint; его route этим ticket не меняется и не получает T1 consumption claim. Native locks, depot/release schema, release_id algorithm, source authority, physics и trust policy не меняются.

**Выбранный API, без dual input/fallback:** exported helper становится `buildSolver(metadataJson: string, expectedGraph: SourceGraph, expectedJuliaManifestSha256: string, execute = run, options = parseBuildOptions([]))`. В нём **нет `spec` argument и нет `target` pathname argument**. Runtime `typeof metadataJson === "string"` обязателен до callback; legacy object/path invocation отвергается, а не coerces в string. Root ops helper — внутренний integration API; оба найденных callers/tests обновляются в одном Root PR. CLI command syntax `solver.ts build DEPOT_JSON ...` и `application_cd.ts DEPOT_JSON ...` сохраняется. Никакого compatibility overload, принимающего unchecked object+path, не остаётся.

**Capture на CLI edge:** каждый CLI читает depot file ровно один раз в captured immutable string. Bounded reader: local regular file, ≤65536 UTF8 bytes; читать максимум65537 bytes, reject oversize/invalid UTF8/raw NUL, descriptor закрывается на всех исходах. Для точного byte accounting UTF8 decode fatal и encode roundtrip должен воспроизвести captured bytes; BOM/unsupported encoding rejected, не молча нормализован. File path/inode — только origin observation; trusted namespace/enrollment authority из него не выводится. Дешёвые regular-file checks before/after open разрешены; защита от malicious FIFO/path-race во время самого capture и hard blocked kernel I/O не заявляется. Если во время capture получены какие-либо bytes, валидируются **они**, а не утверждение об исходном inode version. Никакого позднего read/realPath этого file для Nix после capture нет.

**Validate/bind в самом exported helper:** options проверяются как прежде; captured input bound≤64KiB проверяется и для programmatic string callers. `JSON.parse(metadataJson)` → require non-null non-array top object → validate depot format=`qcl-negf.julia-depot.v1`, Julia=`1.13.0`, exact `juliaManifest`, graph format/root и полный набор `(path, revision, url)` expected graph. Components сравниваются по path после reject duplicates; object key order/array order несущественны; missing/extra entries/изменённые values reject. Expected graph — уже derived `sourceGraph()` в caller, Manifest SHA — штатное измерение existing `julia/Manifest.toml`, не handwritten constant. URL/hash required strings и существующая URL parsing/hash-prefetch admission сохраняются; новой scheme policy/secret scanner этот ticket не вводит.

Из validated parsed object **один раз** получается `boundJson = JSON.stringify(parsedObject)`; неизвестные неиспользуемые metadata fields не превращаются в новую schema policy и сохраняются при serialization. Все operative fields копируются из него в local immutable scalars до первого await/external callback. Normalization явно `JSON.parse→JSON.stringify`: duplicate JSON members разрешаются обычным JS parse до binding, а produced JSON имеет unique serialized members, поэтому Nix не получает второй parser-choice от исходных duplicate members. Не утверждать raw input byte equality после normalization. Validate → serialize → SHA256(TextEncoder(boundJson)) связывает **именно produced bytes**; produced size≤65536 иначе reject до callback. Captured raw bytes SHA/count и produced bytes SHA/count — разные evidence fields. Graph/archive values consumed by Nix и prefetch относятся к одному parsed/normalized value. Не повторно читать metadata file и не передавать caller mutable parsed object.

**Nix edge:** `nix/solver.nix` принимает required strings `depotManifestJson` и `depotManifestSha256` вместо `depotManifest` path. Перед `fromJSON` assert `builtins.hashString "sha256" depotManifestJson == depotManifestSha256`; затем `metadata = builtins.fromJSON depotManifestJson`, unchanged `mkPreparedDepot`/`mkSolver` guards/args. JSON не интерполируется в Nix expression, shell или filename. Передаются exact UTF8 produced string и его digest; argv size ограничен64KiB data + existing fixed args. `builtins.readFile target`/depotManifest pathname в этом entrypoint **удаляется**, fallback отсутствует. Hash assertion — byte attestation same argument, не cryptographic trust root и не native test proof.
