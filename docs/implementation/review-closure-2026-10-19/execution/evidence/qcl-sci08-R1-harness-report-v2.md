B1: `rss_tree` возвращает `None`, если `/proc` исчез, отсутствует VmRSS, единицы/значение неверны либо невозможно прочитать любой discovered task/child. Нулевой total допустим только из реально прочитанных строк VmRSS. После Popen немедленно делается попытка RSS до первого poll, затем периодические attempts. Receipt разделяет attempts, valid observations и unknown; peak начинается `null`, статус при отсутствии valid — `not_measured`. Любой behavioral PASS требует valid≥1 и peak≠null. Быстро завершившийся child без измерения RSS получает STOP с `RSS_not_measured`; завершение или TMP sample не подменяет RSS наблюдение. Возможные transient peaks и межвыборочные forks не доказаны.

TMP теперь имеет отдельные prelaunch/final values и statuses; обе выборки обязательны для pass. Семантика сохранена: сумма logical bytes обычных файлов во всём owned tmp, directory symlinks не traversed. Не заявлены physical allocation, hard disk/memory quotas или native isolation.

Reservation receipt с STOP/attempt_consumed сохраняется до helper preparation и env setup. Любой последующий setup/capture failure сохраняет best-effort diagnostic и failed receipt. При ошибке создания capture bounded nonblocking fallback сохраняет prefix original raw максимум1MiB за≤2s; complete требует наблюдённого EOF, и этот путь всегда STOP. Ничего не удаляется и не обрезается на диске. Нормальный RawCapture сохраняет original bytes; при overflow они остаются на диске и gate не проходит. Bounded readback читает максимум1MiB+1; hash unknown явно `null/not_measured`, если full bounded raw не сверён.

Stop, capture finish, close, TMP final, source final, env final и raw readback имеют независимые exception boundaries; ошибка одного шага не пропускает остальные. Atomic replace сохраняет предыдущий reservation receipt при failed final write; diagnostic при невозможности записи — best-effort stderr. SIGALRM595s направляет SIGKILL только собственной process group, сохраняет failed terminal summaries и вызывает `os._exit(2)`. После двухсекундного finish ещё живой non-daemon reader также приводит к failed receipt и `os._exit(2)`. Это устраняет обычный control-flow путь бесконечного ожидания reader. Не даётся абсолютная гарантия при external guardian kill, зависшем filesystem/kernel или отсутствии CPU scheduling; OS-level supervisor не создавался.
