## 2. Binding strict cleanup contract

V1 §5.5 «R2 не вызывает delete/prune» заменить точным правилом: **R2 не разрешает unconditional failure cleanup; имеющийся successful duplicate/retention cleanup допускается только по отдельной проверенной eligibility/authority цепочке ниже, иначе сохраняется и считается resident.** Будущий unlink никогда не финансирует admission. Новый pruning/retention policy не вводится.

Proposed storage context хранит phase, mutation-started marker, exact registered paths/domains/object identities, source→replacement relationship, last verified boundary, primary exception и monotonic debt. Marker ставится **до** потенциально частично успешного mutator, включая `mkpath/mktemp/open`; после возврата уточняется identity. Ошибка самого create не доказывает отсутствие побочного объекта. Зарезервированный parent/domain containment позволяет консервативно сохранить unknown footprint до reconcile.

Strict temp constructors должны исключать автоматический exit/finalizer cleanup частичных данных; использовать explicit non-auto-cleaning mode, если он поддерживается API. Если этого нельзя гарантировать — branch strict-refused до создания temp. Переименование для «quarantine» не требуется: сохранить in place без нового I/O. Любой rename/receipt для provenance требует ранее выданный соответствующий capability. Нет бесплатного failure receipt, нового registry или cleanup daemon.

Обязательные outcomes:

1. `no_mutation_proven`: authority разрешает release только доказанно не materialized U; неизвестный create не попадает сюда.
2. `partial_unknown`: stage/temp/raw footprint сохранён с exact known identity/domain и lower-bound observed bytes + conservative reserved unknown tail. **Это не validated science data и не completed artifact.** Никакого автоматического parsing/repair/promote. Unknown≠0 и unknown≠pass.
3. `published_unacknowledged`: после rename сохраняется объект нового имени; ledger переносит attribution, не списывает bytes дважды и не закрывает debt как successful. Existing verified pointers/receipt остаются primary recovery evidence.
4. `acknowledged_verified`: существующий применимый verify/receipt/pointer/fsync contract завершён; исходный объект остаётся E в новом lifetime. `return`/close/digest без применимого durability verifier этот статус не создаёт.
5. `cleanup_deferred` или `verified_duplicate_removed`: только для успешного cleanup по правилам ниже. Deferred не отменяет успешно verified scientific payload, но не утверждает выполненный retention maximum или свободные bytes. Counter/high-water не сбрасывается.

**Delete eligibility conjunctive, не guessed:** конкретный объект принадлежит operation/authority; не protected raw/failed/final/unacknowledged/unknown; existing owning retention/duplicate policy разрешает ровно это удаление; replacement независимо проверен, durably acknowledged и полностью покрывает данные/lifetime удаляемого объекта; snapshot/lease/domain/path/object identities ещё совпадают; cleanup имеет разрешённый bounded metadata/I/O capability. Иначе strict writer сохраняет объект и консервативный debt. В частности, invalid receipt не повод для удаления generation.

После разрешённого unlink authority требует **actual unlink evidence** точного объекта и завершения требуемого parent sync/handle/lifetime contract. Запрошенный `rm`, отсутствие exception, rename или `ispath=false` по строке пути сами по себе не доказывают освобождение physical blocks: open fd, aliases, hardlinks, NFS delayed deletion остаются самостоятельными P1 facts. Logical E может быть уменьшен только в доказанной view/attribution; physical H принимается лишь из compatible fresh authority observation, без присвоения H+=filesize. Неизвестный unlink outcome — retained/uncertain debt. Historical high-water и P2 cumulative writes/reads не уменьшаются ни при каком cleanup.

Для ordinary recovery retention strict filter выбирает только independently verified, successfully superseded, policy-eligible acknowledged generations вне защищённых current/previous и вне failed/unacknowledged set, при наличии delete authority. Это сужение текущего потенциально unsafe broad delete, а не научная retention policy. Нет eligibility/authority — prune deferred, весь retained inventory остаётся E; следующий growth может законно быть denied. Если конкретный caller требует немедленный strict retention maximum и deferred outcome для него недопустим, отказать **до** normal growth, не удалять failed данные ради лимита. Никакой выбор нового fallback model/grid/basis.

## 3. ONE I-ready owning ticket: SCI08-R2 strict resident lifecycle

**Owner Runner; один PR, без implementation в D2.** Вход immutable v1+D2+high review/current source hashes. Deliverable объединяет уже ready refusal-only subset и finite writer hooks: baseline arithmetic/typed port; parent+child permit; четыре writer traces и atomic helper; strict preserve-on-failure; guarded successful cleanup eligibility; conservative settlement. C1/P1 backend не реализуется в этом ticket: production default остаётся fail-closed.

Порядок source implementation внутри одного ticket:

1. Сохранить v1 port/arithmetic/R1 strict integer/forecast/cgroup/boot/free guards и standalone signatures/return behavior. Явно протянуть policy/context через scientific execution recovery/final/operator/history-finalizer и staged caller, без standalone fallback из campaign.
2. Guard доминирует над первым mutation у каждой трассы. В strict заменить четыре unconditional cleanup transitions и transitive atomic-helper catch явным context outcome/settlement. Проверить temp auto-cleanup и оборачивающие finalizers по этим call edges. Любой непокрытый transitive mutator/cleanup остаётся strict-refused до writer, а не silently inherited.
3. Сохранить прежний successful publish/fsync/verify/receipt/pointer порядок; same-FS rename не copy. Новый strict cleanup проходит conjunctive eligibility отдельно от publication, без retention credit заранее. Existing broad prune strict-dispatched на guarded selection/defer; standalone прежний путь совместим.
4. Сохранить primary refusal/exception, secondary cleanup/close/settlement failure приложить отдельно с identity; не маскировать primary cause и не выдавать новое разрешение в catch/finally. До первого checkpoint — no_verified_state; после — ссылка на последний acknowledged state. Incomplete arrays остаются `partial_unknown`.
5. Deliver source call/cleanup table и независимые handwritten fixtures. Review отдельно оценивает source diff, доминирование guards и conservation ledger; runtime evidence без grant не выдумывается.
