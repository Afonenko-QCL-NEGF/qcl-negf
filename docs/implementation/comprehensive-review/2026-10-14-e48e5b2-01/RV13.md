## Coordinated snapshot и restore cuts

A2. `ops/state_archive.py::main(create)` требует root, `--writers-paused`, positive finite disk/retention, exact deployed root revision, local `core.psql_dos` profile с matching database/socket/user/empty password и included repository_uri. Проверяет mounted state disk и PostgreSQL data_directory; внешние WAL/nondefault tablespaces отклоняются. `stop_services` останавливает active API/daemon, проверяет empty Slurm queue, затем останавливает scheduler. `pg_dump --format=custom` выполняется при PostgreSQL online; `pack` объединяет этот dump, весь AiiDA directory/repository и Slurm state, после упаковки повторно хеширует captured files.

Это coordinated boundary **при выполненной оператором паузе всех writers**. CLI не блокирует внешние SQL/verdi/repository writers и не берёт RV06 delivery.lock. Проверка пути repository подтверждает configured identity, не удостоверяет логическую связь каждого DB object с repository content; independently mismatched generation под правильным URI может пройти этот structural check. Отдельного generation token в manifest нет. Документ `docs/state-archive.md` прямо требует все submission/writer paths paused до конца: source не обещает обнаружить произвольный заранее рассогласованный dataset. Live storage consistency check остаётся обязательным, отсутствующее свидетельство не заменяется hash match.

A3. `admission` запрещает overwrite archive/sidecar, staging внутри source, лишнюю retention и нехватку disk budget/free space. `source_files` отказывает при links/unsupported entries. `pack` пишет SHA-256/bytes для каждого regular file, сохраняет directory entries, публикует archive hardlink без overwrite и exclusive sidecar. `verify` проверяет archive digest, duplicate members, absolute/`..`/link entries, format, exact regular-file manifest set, digest и bytes каждого member. Это integrity, не trusted origin: sidecar доверяется recovery log. `offhost_backup=not_copied` и `nfs_data=not_included` не скрываются. File/parent fsync для archive publication здесь нет; источник не устанавливает power-loss durability даже после нормального возврата. Копирование на независимый medium и повторный verify — отдельное измерение.

A4. `main(restore)` сначала verify, original state paths, same DB name/PostgreSQL major, empty DB и destination directories; `restore_admission` агрегирует extraction/profile/Slurm/2×physical DB+reserve по `st_dev`, 64MiB headroom на filesystem, retained archive в total budget. Это admission heuristic, не growth quota; state и PostgreSQL root filesystem отклоняются. Лишь затем stop_services/extract/`pg_restore --exit-on-error --single-transaction --no-owner --role=qcl-negf`; DB transaction **заканчивается до** `copytree` repository/Slurm и chown. Failure после DB commit оставляет partial target; automatic rollback/reset отсутствует, повторный restore на непустой DB откажет. Успех тоже не запускает services. Документ явно требует offline target и new empty target либо отдельно рассмотренный cleanup. Неатомарность DB+files не спрятана, и exit code не объявляется complete recovery. Concurrent externally restarted services/CLI during restore не исключены кодом; isolated replacement/disabled automatic startup — операторская предпосылка.

A5. `tests/test_state_archive.py::test_complete_local_state_archive_verifies_and_restores_exact_fixture_bytes` архивирует synthetic dump `PGDMP test fixture`, делает tar extraction и byte comparison; это не `main(restore)` и не PostgreSQL recovery. `test_create_manifest_records_physical_database_size_for_restore` mocks SQL/pg_dump/services/device identities; restore budget tests mocks verify/query/free space и проверяют отказ before stop. `test_checksums_do_not_admit_path_traversal`, corrupt/unsupported/retention assertions задают public negative oracle, но не выполнялись в этом review. Проверки DB-object repository correspondence/UUID и cold bootstrap являются отдельными live gates, не доказанными названиями tests.
