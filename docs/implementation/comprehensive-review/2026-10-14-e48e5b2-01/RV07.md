## Composite export negative case

F07.1 observation: два attempts одного execution с одинаковым result path приводят к duplicate
inventory rejection в `ExportStore.create`, даже если AiiDA публикует однозначную selection.
Если inventories disjoint, `_prepare` открывает plan и каждый path по default `_select_child`,
а create inventory собирает все attempts; selection может отличаться от inventory origin.
Inference: существующий single-file selection guard не распространяется на весь composite
snapshot; API ExportRequest не имеет exact attempt/calcjob selectors. Wrong snapshot availability
и selection change между operations не исключены source-level pinning contract.
Hypothesis о реально смешанном archive не подтверждена: duplicate rejection/lookup failures могут
остановить экспорт раньше. Нельзя назвать corrupted successful archive observed.

Independent oracle: fixture two children с одинаковым размером, различными bytes и plan origins,
published selection2; assert весь inventory/plan/copy/status/cache относятся одной pinned UUID2,
selector change mid-preparation не меняет frozen snapshot. Negative same-path duplicate from
unselected attempt должен либо не попасть в selected inventory, либо дать explicit ambiguity,
не silently выбирая latest. Assert сырой bytes equality, не mocked export success alone.
Existing `test_export_forwards_exact_frozen_plan_bytes_and_source` сохраняет precision text bytes,
но fake service не даёт two-attempt corpus.
