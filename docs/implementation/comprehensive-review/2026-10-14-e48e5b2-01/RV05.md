## Наблюдение, вывод и границы

F05.1 observation: `AiidaService._call/close` ждут Future.result без deadline. Close ставится в
ту же single-owner очередь; зависшая earlier operation не допускает выполнение close/unload.
Source локатор `service.py::_call/close`, counterpart operation AiiDA service source.
Inference: в этом сценарии нет source верхней границы ожидания HTTP/lifespan cleanup. Это
не наблюдённый production hang и не доказательство отказа здорового backend.

F05.2 observation: export cancellation cooperative, reader .read ждёт actor; `_progress`
проверяет cancel только когда control достиг callback. Inference: disconnect fixture с BytesIO
доказывает предусмотренную cleanup структуру для finite operations, не bounded termination
произвольного AiiDA read. Shutdown executor.cancel_futures не завершает уже исполняющийся call.
Hypothesis: stalled ORM/artifact backend задержит shutdown. Runtime experiment не выполнен.

F05.3 observation: test ownership остаётся строгим при parallel clients, а ASGI fixture не
полагается на garbage collection для close. Inference: сохранение owner-thread invariant
важнее произвольного переноса ORM операций в HTTP threads. Fixtures здесь прочитаны, не запущены.

## Oracle/negative и proposal

Независимый oracle следующего selected fixture: управляемый backend Event сигнализирует
«начат и blocked», отдельный client вызывает close/disconnect; witness — deadlines и owner
thread event order. Всегда release Event в finally, чтобы test не зависал. Failure injection
не использует настоящий solver/profile. Различающий отрицательный случай: call blocked до
close; async disconnect во время in-flight read. Healthy finite call остаётся positive control.

Proposal — bounded design ticket [RV05-actor-deadline](fixes/RV05-actor-deadline.md): определить
операционные deadlines и semantics результата «operation outcome unknown». Просто timeout
Future.result не отменяет running ORM/submit и не разрешает повторный submit; acceptance
должен сохранить один owner, artifact lease, known-vs-unknown execution outcome. Автоматический
kill actor/thread или возврат successful close без actual close не предлагается.
