# QCL-NEGF: свидетельства и разбор сессии 27 октября — 3 ноября 2026

**Исполнение программы остановлено по прямому поручению пользователя.** Код компонентов,
установленные системы, VM и данные оставлены без изменений. Два расписания автоматического
продолжения приостановлены. Этот набор документов предназначен для независимого разбора, а не для
автоматического продолжения реализации. PR с отчётами следует оставить открытым; его слияние не
является разрешением на deployment или новый расчёт.

Проблема: планировалось упростить научный проект и получить работающий кластер с переиспользованием
Slurm, AiiDA, NixOS, systemd/cgroup и Proxmox. За неделю существенно выросли Source, тесты и
собственная обвязка, но установленная сквозная система ещё не принята. Пользователь не может
самостоятельно рецензировать такой объём и справедливо ставит под сомнение полезность автономного
исполнения.

  Source/build-script категория:92866→135240; tests/fixtures:78004→145206; schemas:8550→34895. Метод
  и ограничения в01.
- Это большой рост относительно задачи упрощения. LOC сам по себе не доказывает, что конкретная
  функция лишняя, и не измеряет число часов полезной работы.
- Новый научный persistence/public state/независимые readers и часть установочных работ реализованы.
  Results имеет свежий полный1604 PASS/49 явных fixture SKIP. Это не равно работающему
  установленному end-to-end workflow.
- Свежий малый numerical engineering producer уже получал genuine final, но downstream обработка
  упиралась в metadata allowances. Исправления и независимые contract checks подготовлены; новый
  полный путь A128/B512 ещё не исполнен.
- Полный9-case dynamic-memory framework и short-command witness нельзя считать обязательным входом
  любого первого полезного fixed-resource trial. Проверенный conservative/fixed fallback
  предусмотрен исходным планом. Сам fixed path ещё требует настоящих host/guest/Slurm/provenance
  проверок.
- Прежние65% и прогнозы часов сняты как ненадёжные: Source/test progress был переоценён относительно
  installed functional readiness.

## Ответственность и границы

Координатор признаёт ошибку приоритизации: расширенная инфраструктура доказательства готовности
стала обгонять минимальную полезную эксплуатацию. Это не вывод о невозможности кластерной работы QCL
и не доказательство бесполезности всех изменений. В документах сохраняются необходимые
safety/physics invariants и несогласия reviewers.

Публикуются связные обезличенные отчёты, Source commits/symbols, результаты и locators/hash
первичных локальных packets. Не публикуются raw session transcripts, credentials, private
inventories, LAN-адреса, operational UUID, PG/NFS данные или научные массивы. Отсутствующий public
raw artifact отмечается как ограничение проверки, а не выдаётся за доступный читателю файл.
